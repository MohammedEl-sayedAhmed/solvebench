daily loop · verify

./run.sh <problem>

One command tests a problem across every language you solved it in — compiling C++, Java, Go, and Rust on the fly.

  • Solutions self-test and exit non-zero on a wrong answer — no false greens
  • Uses the toolchain container on your host; runs natively inside a Dev Container
  • Filters are fuzzy: two_sum also matches Java's TwoSum

daily loop · start

./run.sh new <url> --lang X

Paste the problem link. The number, title, and difficulty are fetched and the file lands in the right folder — in any of the six languages.

  • LeetCode URLs are resolved via its API; Codewars/HackerRank/AoC links map by slug
  • Java classes are auto-named in PascalCase with the right package
  • Plain paths work too: new leetcode/easy/two_sum --lang py

daily loop · measure

./run.sh complexity <problem>

Empirically measures how your solution scales — runtime and memory across growing inputs, fit to a Big-O class. Works for Python and Java.

  • Inputs are generated from your type hints (Python) or parameter types via reflection (Java)
  • Adversarial defaults — palindromic strings, sequential ints — so early-exits don't fake O(1)
  • JIT warm-up on the JVM; slow solutions stop growing before they hang (--max-seconds)

daily loop · publish

./ship.sh "message"

Your README maintains itself: stats table, per-platform badges, and the solutions index regenerate from the files on disk — then it commits and pushes.

  • Profile links come from profile.json; the index parses each solution's header
  • Refuses to publish if anything private leaks into the tree

tracking

./run.sh --stats

Your progress, grouped by platform × language — the same data that feeds the README badges.

  • Sort it your way: --sort platform · language · status

tracking

./run.sh --time · --changed

Per-solution timings, and a git-aware mode that runs only what you touched — the same check the pre-commit hook uses.

  • --changed diffs against HEAD, so doc-only commits stay instant

environment

./setup.sh

Interactive one-time setup that never touches your machine's global config — everything lands inside the repo.

  • VS Code extensions into .pst/extensions; open with them via ./code.sh
  • pytest into .venv/ (PEP 668-safe); optional pre-commit hook
  • F5 debugging works per language — real breakpoints, no premium subscription

environment · fork

./init.sh

Forked it? One command resets the repo to a clean slate that's yours — and keeps the whole framework.

  • Clears the example solutions and inputs; runner, helpers, templates, and CI stay
  • Writes your handles to profile.json and regenerates the README
  • Optional fresh git history for a clean first commit

environment · undo

./teardown.sh

Everything setup created is reversible — remove it all without leaving a trace on your machine.

  • Deletes .pst/, .venv/, caches and build files; optionally the toolchain image
  • Tracked repo files are never touched
