Everything around the grind, already built

      
You bring the solutions. The framework handles running, debugging,
         tracking, and publishing them.

    

    

      
run.py
        
One polyglot runner

        
Discovers every solution, compiles what needs compiling, and reports
           pass/fail grouped by platform. Wrong answers exit non-zero — no false greens.

      
docker
        
Zero-install, any OS

        
One container image carries all six toolchains. Wrappers for Linux,
           macOS, and Windows; runs natively inside Dev Containers automatically.

      
new.py
        
Scaffold from a URL

        
Paste a LeetCode link — number, title, and difficulty are fetched and
           the file lands in the right folder, in any language.

      
complexity.py
        
Big-O, measured

        
Empirically fits your solution's time and space to a complexity class —
           adversarial inputs, JIT warm-up on the JVM, allocation tracking.

      
F5
        
The debugger, without the subscription

        
Real breakpoints, stepping, and variables in VS Code for any solution —
           what online judges paywall, your editor does better. Per-language configs included.

      
ship.sh
        
Progress that tracks itself

        
Every solve regenerates a stats table, per-platform badges, and the
           solutions index in your README — then commits and pushes. One command.

      
.pst/
        
Self-contained & reversible

        
Extensions, virtualenv, build output — all inside the repo directory.
           teardown.sh removes every trace.

      
ci.yml
        
Green means green

        
GitHub Actions runs the full suite on every push, across all six
           toolchains. Self-testing solutions keep the badge honest.

    

  






  

    

      
The whole loop, four steps

      
From empty fork to a published, tested, complexity-annotated solution.

    

    

      

        
        

          
Fork & reset

          
Fork keeps you in the network graph. init.sh clears the example
             solutions, wires in your handles, and keeps the whole framework.

          
gh repo fork MohammedEl-sayedAhmed/solvebench --clone
cd solvebench && ./init.sh

        

      

      

        
        

          
Set up (optional)

          
Interactive, repo-local: VS Code extensions into .pst/, pytest into
             .venv/, the toolchain image on first run. Nothing global.

          
./setup.sh   # then edit with: ./code.sh

        

      

      

        
        

          
Solve

          
Scaffold from the problem link, debug with F5, verify across every
             language you solved it in, and check how it scales.

          
./run.sh new https://leetcode.com/problems/two-sum/ --lang java
./run.sh two_sum              # ✅ java · ✅ py — all green
./run.sh complexity two_sum   # time ≈ O(n) · space ≈ O(n)

        

      

      

        
        

          
Ship

          
Stats table, badges, and the solutions index regenerate from the files
             on disk — then it commits and pushes.

          
./ship.sh "solve: two sum"

        

      

    

  






  

    

      
Command reference

      
Everything lives in the repo root so commands stay short. Windows:
         same names, .ps1.

    

    

      

        
CommandWhat it does

        
          
./run.sh [filter]Run solutions — container on the host, native inside a Dev Container

          
./run.sh new <url|path> --lang XScaffold a solution; LeetCode URLs auto-fill number/title/difficulty

          
./run.sh complexity <problem>Estimate time & space Big-O empirically (Python and Java)

          
./run.sh --stats · --changed · --timeInventory by platform · only git-changed · with timings

          
./setup.shOne-time interactive setup — everything repo-local

          
./code.shVS Code scoped to this repo (isolated extensions + profile)

          
./ship.sh "msg"Refresh README stats/index, commit, push

          
./teardown.shRemove everything setup created

          
./init.shFork clean-slate: clear examples, set your handles

          
common.TestFrameworkThe self-test helper every solution calls — copy-paste cheat sheet: check & checkUnordered
